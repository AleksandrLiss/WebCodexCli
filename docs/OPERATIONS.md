# Эксплуатация, обновление и перенос

Примеры ниже используют стандартные имена и выполняются из корня проекта. Для нестандартного env-файла используйте `python3 scripts/manage.py --env-file PATH <command>`.

## Ручной запуск и остановка

```bash
./scripts/start.sh
./scripts/stop.sh
./scripts/status.sh
docker logs --tail 100 codex-web
docker stats --no-stream codex-web
```

Контейнер настроен на `restart: "no"`: после перезагрузки ОС или перезапуска Docker сервис автоматически не запускается. После входа на сервер выполните `./scripts/start.sh`. Команды доступны по абсолютному пути, например `/root/codex-web/scripts/start.sh`, и не зависят от текущего каталога. Для непривилегированного пользователя может потребоваться `sudo`.

Start запускает существующий контейнер, не пересобирает образ и ждёт healthcheck до 60 секунд. Stop останавливает контейнер с grace period 15 секунд, не удаляя его или volumes. Повторные команды не пересоздают контейнер. Оба скрипта проверяют принадлежность контейнера проекту и отключают старую restart policy, если она ещё была включена.

Docker daemon может запускаться с ОС, но приложение остаётся остановленным до ручного старта. После падения процесса или OOM контейнер тоже не перезапускается автоматически; восстановление выполняет владелец через start. Проверка состояния: `./scripts/status.sh`.

Остановка завершает активные PTY-процессы и отзывает web-cookie. Рабочие файлы и история CLI сохраняются в named volumes. Healthcheck сообщает о состоянии HTTP-сервера; Docker не перезапускает контейнер только из-за состояния unhealthy.

## Обновление

```bash
git pull --ff-only
./scripts/backup.sh ../backups/before-update-2026-10-05
./scripts/update.sh
```

Резервное копирование и обновление останавливают активные сессии. Сначала завершите нужные задачи. Сборка нового образа выполняется до остановки старого контейнера. При ошибке сборки старый контейнер продолжает работать.

При замене старый контейнер останавливается и переименовывается в `codex-web-previous-<timestamp>-<suffix>`. Новый контейнер получает прежнее имя и те же volumes. Если он не проходит healthcheck, скрипт удаляет созданный им новый контейнер, возвращает старому имя и запускает его, если он работал до обновления.

При успешном обновлении старый контейнер остаётся остановленным. Его точное имя выводится в консоль. Скрипты не удаляют volumes и не выполняют `docker system prune`.

Если образ уже собран или изменяется только `.env`:

```bash
./scripts/update.sh --skip-build
```

Не запускайте параллельно несколько start/stop/deploy/update/backup/restore для одного окружения. Выберите единый способ управления: CLI-скрипты или Docker Compose. Compose не предоставляет автоматический откат, описанный выше. Deploy/update запускают контейнер по явной команде владельца; restart policy остаётся `no`, в том числе после rollback.

## Ручной откат

Используйте точное имя предыдущего контейнера, выведенное update:

```bash
docker stop codex-web
docker rename codex-web codex-web-failed-20261005
docker rename codex-web-previous-<timestamp>-<suffix> codex-web
docker start codex-web
python3 scripts/manage.py status
```

Откат контейнера возвращает старый образ и его env, но не отменяет изменения в общих volumes. Для возврата состояния файлов потребуется отдельная резервная копия. Проверьте соответствие текущего `.env` настройкам возвращённого контейнера.

После подтверждения успешного обновления старый контейнер можно удалить по его точному имени: `docker rm <previous-name>`. Не удаляйте предыдущий образ до истечения нужного вам срока отката.

## Резервная копия

```bash
./scripts/backup.sh ../backups/codex-web-20261005
```

Путь должен быть новым: существующая папка не перезаписывается. Скрипт проверяет соответствие actual mounts настройкам, останавливает приложение, потоково архивирует оба volumes, копирует `.env`, создаёт manifest и запускает приложение обратно. При ошибке архивации ранее работавший контейнер также запускается обратно. Незавершённая копия без manifest не считается валидной.

| Файл копии | Содержимое |
| --- | --- |
| `workspace.tar.gz` | Проекты и рабочие файлы |
| `codex-home.tar.gz` | Авторизация, конфигурация и история CLI |
| `.env` | Пароль web-интерфейса и параметры запуска |
| `manifest.json` | Формат 1, время создания, SHA-256 всех трёх файлов |

Папка имеет права 700, файлы — 600. Копия содержит действующие секреты. Она переносится отдельно от исходников, например через `scp`, и не загружается в Git. SHA-256 выявляет повреждение; manifest не является криптографической подписью. Восстанавливайте только свою доверенную копию.

Вспомогательный контейнер архивации использует имеющийся образ, `--network none`, read-only root filesystem, uid 1000, лимит 64 МБ и 0.25 CPU. Пользовательские volumes монтируются только для соответствующей операции.

## Перенос на новый сервер с новым web-паролем

1. На старом сервере создайте копию и перенесите её по SSH.
2. На новом сервере установите Docker и загрузите исходники.
3. Сгенерируйте `.env`, соберите или загрузите образ, восстановите данные и запустите приложение:

```bash
python3 scripts/manage.py init-env
python3 scripts/manage.py build
./scripts/restore.sh /path/to/private-backup
./scripts/deploy.sh --skip-build
```

Сохраняется новый `.env`, поэтому web-пароль может отличаться. Авторизация CLI и разговоры приходят из `codex-home.tar.gz`. Копия логина обновляется независимо от старого сервера; при недействительных credentials выполните вход заново.

## Полный перенос с прежним web-паролем

На новом сервере подготовьте образ, затем отложите созданный новый env:

```bash
python3 scripts/manage.py init-env
python3 scripts/manage.py build
mv .env .env.generated-before-migration
./scripts/restore.sh /path/to/private-backup --use-backup-env
./scripts/deploy.sh --skip-build
```

`--use-backup-env` работает только при отсутствующем `.env` и восстанавливает весь файл, включая имена volumes, порт и bind address. Если в копии задан IP старого сервера, замените его до запуска. Файл `.env.generated-before-migration` также содержит пароль и игнорируется Git.

Restore проверяет manifest/checksums и имена archive members до работы с Docker. Уже существующий целевой контейнер или непустые volumes приводят к отказу. Данные не перезаписываются автоматически. При ошибке посреди извлечения частично восстановленные volumes остаются на месте для диагностики; для повторной попытки выберите новые имена volumes в `.env`.

Symlink внутри архива допускается, если его нормализованный target остаётся внутри volume. Абсолютные ссылки, выходящие за его пределы ссылки, device nodes и path traversal отклоняются. Это ограничение может потребовать заново установить зависимости проекта с внешними symlink после переноса.

## Авторизация и настройки CLI

```bash
python3 scripts/manage.py import-auth /secure/path/auth.json
docker exec codex-web codex login status
```

Импорт читает локальный JSON и передаёт его через stdin внутри контейнера, создавая файл с правами 600 от uid 1000. Cache не включается в образ. Альтернатива — создать web-сессию «Вход в ChatGPT». Авторизация описана в [official OpenAI documentation](https://learn.chatgpt.com/docs/auth).

Настройки модели находятся в `/home/codex/.codex/config.toml`. Их можно менять в Bash-сессии. Перезапускать весь контейнер не требуется; новую конфигурацию использует следующая CLI-сессия.

## Диагностика

| Симптом | Проверка / действие |
| --- | --- |
| Порт недоступен | `docker ps`, `docker logs`, `WEB_BIND_ADDRESS`, NAT/firewall провайдера |
| Не подходит пароль | `WEB_PASSWORD` из env; после изменения выполнить update `--skip-build` |
| Сессия не создаётся | Завершить одну из двух активных; проверить существование cwd |
| Нет ответа модели | `codex login status`, реальный ответ CLI, доступность сети и выбранной модели |
| Sandbox не запускает команду | Проверить user namespaces/seccomp хоста; обработать запрос подтверждения CLI |
| Контейнер неожиданно перезапустился | `docker inspect codex-web`, `State.OOMKilled`, логи и лимиты RAM/PIDs |
| Приложение после ребута остановлено | Штатный ручной режим; выполнить `./scripts/start.sh` |
| Docker daemon недоступен | `systemctl status docker`; при необходимости запустить Docker |
| Restore отказывается работать | Корректные SHA-256, новый контейнер/пустые volumes, доверенные archive members |
| Legacy builder недоступен | Собрать образ на другой машине и перенести через `export-image.sh` |

Показать признаки завершения и перезапусков без вывода env с паролем:

```bash
docker inspect codex-web --format 'Running={{.State.Running}} OOM={{.State.OOMKilled}} Restarts={{.RestartCount}}'
```
