# HTTP API и WebSocket

Базовый URL по умолчанию: `http://<server>:8080`. JSON-запросы передаются с `Content-Type: application/json`. Лимит HTTP body и входящего WebSocket message — 65 536 байт. Cookie и данные авторизации CLI не возвращаются в JSON API.

## Маршруты

| Метод | URL | Авторизация | Результат |
| --- | --- | --- | --- |
| GET | `/` | Нет | HTML интерфейса |
| GET | `/static/...` | Нет | CSS/JS, без listing каталогов |
| GET | `/healthz` | Нет | `{"ok": true}` |
| POST | `/api/login` | Пароль в body + Origin | Cookie и `{"ok": true}` |
| POST | `/api/logout` | Cookie + Origin | Удаление токена входа |
| GET | `/api/status` | Cookie | Статус CLI и рабочая папка |
| GET | `/api/sessions` | Cookie | Список web-сессий |
| POST | `/api/sessions` | Cookie + Origin | Создание сессии, HTTP 201 |
| DELETE | `/api/sessions/{id}` | Cookie + Origin | Остановка и удаление сессии |
| GET / upgrade | `/api/sessions/{id}/ws` | Cookie + Origin | Двунаправленный терминал |

Origin должен содержать такой же host и port, как HTTP Host. Например, при обращении к `127.0.0.1:8080` используйте `Origin: http://127.0.0.1:8080`. Cookie после входа передаётся браузером автоматически.

## Вход

```json
{"password": "<WEB_PASSWORD>"}
```

Не передавайте пароль в URL. Cookie `codex_web` живёт 12 часов, но серверный токен также удаляется при выходе или перезапуске приложения. Выйти из web-интерфейса не означает остановить все CLI-сессии.

## Статус

```json
{"authenticated": true, "workspace": "/workspace", "version": "0.160.0"}
```

`authenticated` основан на exit code `codex login status` с timeout пять секунд. Это проверка локальной авторизации CLI, а не запрос к модели.

## Создание сессии

```json
{"kind": "codex", "cwd": "/workspace", "cols": 100, "rows": 30}
```

Поля необязательны; показаны значения по умолчанию. `kind` принимает `codex`, `resume`, `shell`, `login`. Путь разрешается сервером; папка должна существовать внутри `/workspace`. Не существует отдельного HTTP API для произвольного запуска команд: ввод передаётся через терминальный WebSocket.

Пример объекта сессии:

```json
{"id": "0123456789abcdef01234567", "kind": "shell", "cwd": "/workspace", "created": 1790964000.0, "exited": false, "exitCode": null}
```

`created` — Unix timestamp в секундах. `exitCode` содержит код завершения процесса; отрицательное значение означает сигнал. Сессии принадлежат общему рабочему пространству, а не отдельному токену входа.

## Протокол WebSocket

Все сообщения — JSON text frames. Клиент → сервер:

```json
{"type": "input", "data": "pwd\r"}
```

```json
{"type": "resize", "cols": 110, "rows": 35}
```

Enter передаётся как `\r`, Ctrl C — как `\u0003`, Escape — как `\u001b`. Терминальные escape sequences остаются в строках и обрабатываются xterm.js.

Сервер → клиент:

```json
{"type": "output", "data": "...вывод терминала..."}
```

```json
{"type": "exit", "code": 0}
```

Первое событие output содержит сохранённый буфер. Если процесс уже завершён, после него приходит exit. Закрытие сокета не завершает процесс. Heartbeat задаётся с интервалом 20 секунд.

| Close code | Значение |
| --- | --- |
| 4001 | Токен входа истёк или отозван |
| 4002 | Переполнена очередь клиента; переподключиться для воспроизведения буфера |
| 1008 | Некорректный JSON или размер терминала |

## HTTP-ошибки

| Код | Причина |
| --- | --- |
| 400 | Некорректный JSON, тип сессии, папка или размеры |
| 401 | Неверный пароль или отсутствует действующая cookie |
| 403 | Отсутствует или не совпадает Origin |
| 404 | Сессия или ресурс не найдены |
| 409 | Уже есть две активные сессии |
| 413 | Body превышает лимит |
| 429 | Превышено число попыток входа |

Ошибки могут возвращаться plain text; клиент не должен всегда ожидать JSON при non-2xx.
