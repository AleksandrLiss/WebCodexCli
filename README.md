# Codex Workspace

Веб-интерфейс к Codex CLI: интерактивный терминал xterm.js, две параллельные сессии, Bash, выбор папки проекта, восстановление соединения, история Codex и вход в ChatGPT через device code. Интерфейс на русском, адаптирован для телефона.

Проект подготовлен для Git и переноса на другой Linux-сервер. Пароль, авторизация ChatGPT и пользовательские проекты в исходники не входят.

Сервис работает в ручном режиме: после перезагрузки ОС контейнер не запускается автоматически.

## Запуск

На новом сервере с Docker, Python 3 и Bash:

```bash
cd codex-web
python3 scripts/manage.py init-env
./scripts/deploy.sh --dry-run
./scripts/deploy.sh
```

Если Docker отсутствует, сначала выполните `sudo ./scripts/install-docker.sh` на Ubuntu или Debian. Скрипт не меняет уже установленный Docker. Команда `./run.sh` сохранена как сокращение для `./scripts/deploy.sh`.

Открыть `http://localhost:8080` или `http://<IP-сервера>:8080`. Пароль автоматически создаётся в `.env` (доступ только владельцу):

```bash
cat .env
```

Если установлен Docker Compose, после `python3 scripts/manage.py build` можно выполнить `docker compose up -d --no-build`. Выберите один способ управления контейнером: Compose или скрипты. Оба способа используют настройки `.env` и те же имена volumes.

## Ручное управление после установки

После входа на сервер:

```bash
/root/codex-web/scripts/start.sh   # Запустить существующий контейнер
/root/codex-web/scripts/stop.sh    # Остановить сервис
/root/codex-web/scripts/status.sh  # Проверить состояние
```

Если проект установлен в другую папку, замените `/root/codex-web` её путём. Для доступа к Docker и конфигурации при необходимости используйте `sudo`. Из корня проекта доступны те же команды как `./scripts/start.sh`, `./scripts/stop.sh`, `./scripts/status.sh`.

`start.sh` дожидается healthcheck, `stop.sh` завершает активные терминальные процессы. Повторные start/stop безопасны. Ни скрипты, ни Compose не включают автозапуск после reboot; пароль, файлы и история остаются в volumes. `deploy.sh` нужен для первой установки, `update.sh` — для обновления.

По умолчанию сборка ограничена 256 МБ памяти и половиной CPU, контейнер — 384 МБ памяти и 0.75 CPU. Конфигурация рассчитана на небольшой VDS; для больших проектов лимиты задаются в `.env`. При наличии работающего контейнера обычный deploy проверяет его здоровье и не пересоздаёт.

## Работа

- «Запустить Codex» → выбрать существующую папку внутри `/workspace` → «Создать сессию».
- «Открыть терминал» запускает Bash; здесь можно клонировать репозиторий (`git clone URL /workspace/project`) или создать папку.
- «Новая сессия» → «Codex — продолжить из истории» открывает стандартный выбор сохранённых разговоров Codex.
- Кнопки Ctrl C, Esc, Enter и размер шрифта доступны над терминалом. Терминал поддерживает вставку текста обычными клавишами браузера.
- При закрытии вкладки процессы продолжают работать. После перезапуска контейнера процессы завершаются; история Codex и файлы остаются в volumes. Продолжить разговор можно через историю.
- Одновременно доступны до двух активных сессий. Приложение рассчитано на одного владельца: все вкладки видят общие сессии.

## Авторизация Codex

Для нового развёртывания нажмите «Войти в ChatGPT» и выполните инструкции `codex login --device-auth` в терминале. При необходимости включите вход по коду устройства в настройках ChatGPT.

Можно также импортировать существующую авторизацию без включения её в образ:

```bash
python3 scripts/manage.py import-auth ~/.codex/auth.json
```

Способы авторизации сверены с [official OpenAI documentation](https://learn.chatgpt.com/docs/auth). Копия авторизации обновляется независимо от файла хоста; если она перестанет работать, войдите заново через интерфейс.

## Хранение и управление

| Docker volume | В контейнере | Данные |
| --- | --- | --- |
| `codex-web-workspace` | `/workspace` | Проекты и файлы |
| `codex-web-home` | `/home/codex/.codex` | Авторизация, настройки и история Codex |

```bash
docker logs --tail 100 codex-web
docker restart codex-web
docker stop codex-web
docker start codex-web
tar -C ./my-project -cf - . | docker exec -i codex-web sh -c 'mkdir -p /workspace/my-project && tar --no-same-owner -xf - -C /workspace/my-project'
```

Обновление приложения с сохранением данных и автоматическим возвратом предыдущего контейнера при ошибке запуска:

```bash
./scripts/update.sh
```

Изменения `.env` применяются через `./scripts/update.sh --skip-build`. Новая версия образа собирается до остановки старой. После успешного обновления предыдущий контейнер остаётся остановленным для ручного отката; volumes общие. Подробности: [эксплуатация](docs/OPERATIONS.md).

## Устройство

Python 3.12 + aiohttp, системный PTY, WebSocket, локальные ресурсы xterm.js. Codex CLI зафиксирован на 0.160.0; Python-зависимости — в `requirements.lock`. Образ содержит Git, curl, ripgrep, Python, Node.js и npm. CLI запускается от пользователя `codex`, с `workspace-write` и подтверждением `on-request`; запросы подтверждения показываются прямо в терминале. Контейнер запускается без дополнительных capabilities и без Docker socket или доступа к каталогам хоста.

Вход в интерфейс защищён отдельным паролем, HttpOnly cookie, проверкой Origin и ограничением числа попыток. Внешний порт: 8080. Для доступа через публичную сеть используйте HTTPS-прокси или SSH-туннель: HTTP сам по себе не шифрует пароль и содержимое терминала.

## Проверка

Проверка исходников и скриптов без пересборки, модели и изменения работающего контейнера:

```bash
./scripts/validate.sh
```

Интеграционный smoke-тест выполняется в запущенном контейнере и создаёт временную Bash-сессию. Требуется свободное место среди двух активных сессий:

```bash
docker cp tests/smoke.py codex-web:/tmp/smoke.py
docker exec codex-web python /tmp/smoke.py
curl -f http://127.0.0.1:8080/healthz
```

Проверка выполняет реальные команды Bash: вход, защита API и WebSocket, ввод/вывод PTY, размер терминала, Ctrl C, переподключение, выход и закрытие процесса. Запросы к модели в этом тесте не выполняются.
